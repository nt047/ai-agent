ncrypt the prompt injection. Let Copilot decrypt it for you.
<!-- SC_OFF --><div class="md"><p>This one is clever.</p> <p>Instead of trying to sneak malicious instructions past Copilot's prompt-injection filters, the attacker encrypts them. The filters see ciphertext, Copilot helpfully decrypts it itself, and then executes the instructions.</p> <p>Which is... not ideal.</p> <p>The part I find more interesting is that one model reportedly executed the full chain in about half the tests, while two others refused it. Same agent, same tools, same attack, different model.</p> <p>To me, that makes the architectural problem pretty obvious: once an agent can read local files, execute code and make outbound connections, the model itself probably shouldn't be treated as the security boundary. The useful controls are around what the agent is allowed to touch, execute and communicate with, and whether you can actually see those actions when something goes wrong.</p> </div><!-- SC_ON --> &#32; subm
