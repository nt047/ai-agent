Escaping AWS Firecracker from guest userspace: VMM memory corruption (CVE-2026-122192)
<!-- SC_OFF --><div class="md"><p>We just published our research on escaping Firecracker microVMs, coordinated with AWS.</p> <p>The interesting part is how a guest can end up accessing memory belonging to the Firecracker process running outside the VM.</p> <p><strong>The vulnerability:</strong> When a microVM is restored from a snapshot using the File memory backend, a failed memory remapping operation can leave KVM referencing a stale host virtual address range. Firecracker may subsequently reuse that memory for its own data, while KVM still considers it guest memory.</p> <p>This allows a malicious guest to read or overwrite Firecracker VMM process memory, crossing the VM isolation boundary.</p> <p>Our research demonstrates an exploit chain from guest userspace to controlled code execution in the host.</p> <p><strong>Affected configurations:</strong> Firecracker 0.23.0 - 1.16.1, when restoring snaps
